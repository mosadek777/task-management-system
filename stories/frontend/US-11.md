# US-11 — Delete a task with confirmation

| Field | Value |
|---|---|
| **ID** | US-11 |
| **Layer** | Frontend |
| **Actor** | Task owner |
| **Consumes endpoint** | `DELETE /api/tasks/{id}` (US-05) |
| **Spec user story** | Story 5 — Remove a task (P2) |
| **Priority** | P2 |

## Description

As the task owner, I want to delete a task from the list, and be asked to confirm first, so that I
cannot destroy work with a single mis-click. Because deletion is permanent and there is no undo,
the confirmation is the only safeguard the person has.

## Acceptance criteria

- **AC-11.1** — Each task in the list offers a delete action.
- **AC-11.2** — Choosing delete asks the person to confirm before anything is sent to the server.
- **AC-11.3** — The confirmation names the task being deleted, so the wrong row cannot be removed
  by accident.
- **AC-11.4** — The confirmation makes clear the removal is permanent and cannot be undone.
- **AC-11.5** — Declining the confirmation sends nothing and leaves the task untouched.
- **AC-11.6** — Confirming deletes the task and removes it from the list without a manual reload.
- **AC-11.7** — If the task was already deleted elsewhere, the resulting "not found" is handled
  gracefully — the row disappears and a readable message is shown, never an unhandled failure.
- **AC-11.8** — If the delete request fails, the task remains in the list and an error message is
  shown, so the display never disagrees with what is actually stored.

## Traceability

**Satisfies**: FR-014, FR-015, FR-016

**Depends on**: US-05

**Verified by success criteria**: SC-004, SC-008, SC-009

## Out of scope

Undo, restore or a recycle bin — deletion is permanent by decision Q3. Bulk deletion. Deleting
from within the edit form.

## Definition of done

Verified in the browser: declining leaves the task present, confirming removes it, and deleting an
already-deleted task produces a readable message rather than a broken screen.
