# US-12 — Search tasks by title from the list

| Field | Value |
|---|---|
| **ID** | US-12 |
| **Layer** | Frontend |
| **Actor** | Task owner |
| **Consumes endpoint** | `GET /api/tasks?search={text}` (US-06) |
| **Spec user story** | Story 6 — Find a task by name (P3) |
| **Priority** | P3 |

## Description

As the task owner, I want a search box above my list so that I can type part of a task's name and
see only the matching tasks, instead of scanning everything.

## Acceptance criteria

- **AC-12.1** — A search input is available above the list.
- **AC-12.2** — Typing a fragment narrows the list to titles containing that fragment.
- **AC-12.3** — Matching ignores case, mirroring the server behaviour.
- **AC-12.4** — Searching is performed by the server through the list request — the client does
  not fetch everything and filter in the browser.
- **AC-12.5** — A search matching nothing shows an explanatory empty state naming the term
  searched, distinct from the "no tasks at all" empty state.
- **AC-12.6** — Clearing the search restores the full list.
- **AC-12.7** — A visible control clears the search in one action.
- **AC-12.8** — Typing does not fire one request per keystroke; input is debounced or submitted
  deliberately.
- **AC-12.9** — An active search survives a create, edit or delete — the narrowed view is
  reapplied rather than silently resetting to everything.
- **AC-12.10** — A failed search request shows a readable error and leaves the previous results
  visible.

## Traceability

**Satisfies**: FR-017, FR-018, FR-020, FR-021, FR-027

**Depends on**: US-06, US-08

**Verified by success criteria**: SC-005, SC-008

## Out of scope

Server-side search behaviour itself (US-06). Match highlighting. Search history or suggestions.
Searching descriptions.

## Definition of done

Verified in the browser: a mid-word match, a case-mismatched match, a term matching nothing, and
clearing the search restoring the full list.
