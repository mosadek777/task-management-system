# US-08 — View the task list

| Field | Value |
|---|---|
| **ID** | US-08 |
| **Layer** | Frontend |
| **Actor** | Task owner |
| **Consumes endpoint** | `GET /api/tasks` (US-02) |
| **Spec user story** | Story 2 — See everything on the list (P1) |
| **Priority** | P1 |

## Description

As the task owner, I want to see all my tasks on one screen so that I know what I have to do. The
list shows each task's title, importance, state and due date, with the most recently captured
first, and offers the actions that operate on a task.

## Acceptance criteria

- **AC-08.1** — Opening the application loads and displays every task.
- **AC-08.2** — Each row shows title, importance, state and due date.
- **AC-08.3** — A task with no due date renders cleanly — a dash or "No due date" — never a blank
  gap, an invalid date, or the literal word "null".
- **AC-08.4** — Tasks appear newest first, matching the order returned by the server.
- **AC-08.5** — Importance and state are shown as readable labels — "In Progress", not
  "InProgress" — and are visually distinguishable at a glance.
- **AC-08.6** — While the list is loading, a loading indication is shown rather than an empty
  screen that looks like a failure.
- **AC-08.7** — With no tasks stored, an explanatory empty state is shown inviting the person to
  create their first task — not an error and not a blank page.
- **AC-08.8** — If the request fails, a readable error message is shown and the application stays
  usable.
- **AC-08.9** — Each row offers edit and delete actions, and a way to see the task's full detail.
- **AC-08.10** — After any create, edit or delete, the list reflects the change without the person
  manually reloading the page.
- **AC-08.11** — The layout is styled with Tailwind utility classes only and is usable at both
  desktop and narrow widths.

## Traceability

**Satisfies**: FR-006, FR-007, FR-008, FR-027, FR-029

**Depends on**: US-02

**Verified by success criteria**: SC-007, SC-008

## Out of scope

Search (US-12) and filter (US-13) controls. Sorting chosen by the person. Paging. Inline editing
within a row.

## Definition of done

Verified in the browser with zero tasks, with several tasks, with a task lacking a due date, and
with the backend stopped to confirm the error state.
