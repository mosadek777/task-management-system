# US-09 — Create a task through a form

| Field | Value |
|---|---|
| **ID** | US-09 |
| **Layer** | Frontend |
| **Actor** | Task owner |
| **Consumes endpoint** | `POST /api/tasks` (US-01) |
| **Spec user story** | Story 1 — Capture a task (P1) |
| **Priority** | P1 |

## Description

As the task owner, I want a form to capture a new task so that I can record work quickly. The form
validates my input before submitting, so I am told about mistakes immediately rather than after a
round trip.

## Acceptance criteria

**Form and submission**

- **AC-09.1** — The form offers title, description, importance, state and due date.
- **AC-09.2** — Importance and state are chosen from fixed lists, so an invalid value cannot be
  typed.
- **AC-09.3** — Importance defaults to Medium and state defaults to Todo.
- **AC-09.4** — Description and due date can be left empty and the form still submits.
- **AC-09.5** — A successful save returns the person to the list, where the new task is visible
  without a manual reload.
- **AC-09.6** — The submit control is disabled while a save is in flight, so one click cannot
  create two tasks.

**Client-side validation** *(this story carries the client-validation requirement for creation)*

- **AC-09.7** — An empty or whitespace-only title shows an inline error and blocks submission.
- **AC-09.8** — A title over 200 characters shows an inline error naming the limit and blocks
  submission.
- **AC-09.9** — A description over 1000 characters shows an inline error naming the limit and
  blocks submission.
- **AC-09.10** — Error messages appear next to the field they concern, not only in a summary.
- **AC-09.11** — Validation messages appear once the person has touched or submitted the field —
  a pristine untouched form does not shout errors on open.
- **AC-09.12** — A due date in the past is accepted without warning; there is no date restriction.
- **AC-09.13** — Client validation mirrors the server rules but never replaces them. If the server
  still rejects the submission, its message is displayed to the person and the form keeps the
  entered values so nothing is retyped.

## Traceability

**Satisfies**: FR-001, FR-002, FR-004, FR-023, FR-025 · client-validation requirement (creation)

**Depends on**: US-01

**Verified by success criteria**: SC-001, SC-003, SC-008

## Out of scope

Editing an existing task (US-10). Draft autosave. Creating several tasks at once.

## Definition of done

Verified in the browser: a title-only save, a full save, each validation rule rejecting, and a
server-side rejection surfacing without losing the typed values.
