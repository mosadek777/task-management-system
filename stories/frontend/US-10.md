# US-10 — Edit a task through a form

| Field | Value |
|---|---|
| **ID** | US-10 |
| **Layer** | Frontend |
| **Actor** | Task owner |
| **Consumes endpoints** | `GET /api/tasks/{id}` (US-03), `PUT /api/tasks/{id}` (US-04) |
| **Spec user story** | Story 4 — Keep a task up to date (P2) |
| **Priority** | P2 |

## Description

As the task owner, I want to open an existing task in a form pre-filled with its current values so
that I can correct details, adjust importance or due date, and move it through Todo → InProgress →
Done.

## Acceptance criteria

**Loading and saving**

- **AC-10.1** — Opening a task for editing pre-fills every field with its stored values.
- **AC-10.2** — An absent description or due date renders as genuinely empty, not as "null" or an
  invalid date.
- **AC-10.3** — The stored due date appears in the date control correctly, without shifting by a
  day.
- **AC-10.4** — Changing the state to Done and saving is reflected in the list immediately.
- **AC-10.5** — A successful save returns the person to the list showing the updated values.
- **AC-10.6** — Cancelling leaves the task completely unchanged.
- **AC-10.7** — Description and due date can each be cleared back to empty and saved as absent.
- **AC-10.8** — Opening a task that no longer exists shows a "not found" message and returns the
  person to a usable screen rather than an empty broken form.
- **AC-10.9** — The identifier and capture moment are displayed as read-only context, or not shown
  at all — they are never editable.

**Client-side validation** *(this story carries the client-validation requirement for editing)*

- **AC-10.10** — The same rules as US-09 apply: title required and non-blank, title at most 200
  characters, description at most 1000 characters.
- **AC-10.11** — Emptying the title blocks submission with an inline error.
- **AC-10.12** — A server-side rejection is displayed and the form keeps the person's edits.

## Out of scope

Creating a task (US-09). Inline editing inside a list row. Change history. Conflict detection when
the same task is changed elsewhere.

## Definition of done

Verified in the browser: every field changed and saved, a due date cleared, the title emptied and
rejected, a state advanced to Done, and a deleted task opened for editing showing "not found".
