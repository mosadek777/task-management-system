# US-03 — Retrieve a single task by identifier

| Field | Value |
|---|---|
| **ID** | US-03 |
| **Layer** | Backend |
| **Actor** | Task owner |
| **Linked endpoint** | `GET /api/tasks/{id}` |
| **Spec user story** | Story 3 — Inspect one task in full (P2) |
| **Priority** | P2 |

## Description

As the task owner, I want to retrieve one specific task by its identifier so that I can see its
complete detail — including the full description that the list view shortens — and so the edit
form can be populated with its current values.

## Acceptance criteria

- **AC-03.1** — Requesting an existing task responds `200 OK` with that task.
- **AC-03.2** — The response contains every stored value: identifier, title, full untruncated
  description, importance, state, due date and capture moment.
- **AC-03.3** — Requesting an identifier that does not exist responds `404 Not Found` with a
  message saying the task was not found.
- **AC-03.4** — A `404` response changes nothing and creates nothing.
- **AC-03.5** — Requesting a deleted task responds `404`.
- **AC-03.6** — An identifier that is not a valid identifier at all is rejected with `400` rather
  than causing a failure.
- **AC-03.7** — The database is queried asynchronously.

## Traceability

**Satisfies**: FR-009, FR-026

**Verified by success criteria**: SC-009

## Out of scope

Displaying the detail (US-08, US-10). Retrieving several tasks at once (US-02).

## Definition of done

Demonstrated in Swagger for an existing identifier, a well-formed identifier that does not exist,
and a malformed identifier.
