# US-02 — Retrieve all tasks

| Field | Value |
|---|---|
| **ID** | US-02 |
| **Layer** | Backend |
| **Actor** | Task owner |
| **Linked endpoint** | `GET /api/tasks` |
| **Spec user story** | Story 2 — See everything on the list (P1) |
| **Priority** | P1 |

## Description

As the task owner, I want to retrieve every task I have captured so that my list can be displayed.
With no narrowing applied, the whole collection is returned in a single response, most recently
captured first.

## Acceptance criteria

- **AC-02.1** — A request with no parameters responds `200 OK` with every stored task.
- **AC-02.2** — Each returned task carries its identifier, title, description, importance, state,
  due date and capture moment.
- **AC-02.3** — Tasks are ordered by capture moment, newest first.
- **AC-02.4** — When no tasks exist, the response is `200 OK` with an empty collection — never
  `404`, never an error.
- **AC-02.5** — The response is a plain collection: no paging, no page size, no total count and no
  wrapper envelope.
- **AC-02.6** — Every task the caller has stored appears; nothing is hidden or filtered out by
  default.
- **AC-02.7** — Tasks that have been deleted never appear.
- **AC-02.8** — The database is queried asynchronously.

## Traceability

**Satisfies**: FR-006, FR-007, FR-008, FR-027, FR-029

**Verified by success criteria**: SC-007

## Out of scope

Narrowing by title (US-06) or state (US-07) — this story covers the unnarrowed collection only.
Rendering the list (US-08). Caller-controlled sorting.

## Definition of done

Demonstrated in Swagger with an empty store and with several stored tasks, confirming order and
the empty-collection behaviour.
