# US-06 — Search tasks by title

| Field | Value |
|---|---|
| **ID** | US-06 |
| **Layer** | Backend |
| **Actor** | Task owner |
| **Linked endpoint** | `GET /api/tasks?search={text}` |
| **Spec user story** | Story 6 — Find a task by name (P3) |
| **Priority** | P3 |

## Description

As the task owner, I want to narrow the task list to those whose title contains a fragment of text
so that I can find a specific task without scanning the whole list. Search is a parameter on the
existing list endpoint, not an endpoint of its own.

## Acceptance criteria

- **AC-06.1** — Supplying a search term responds `200 OK` with only those tasks whose title
  contains that term.
- **AC-06.2** — Matching is a substring test anywhere in the title, not only at the beginning —
  searching `rep` returns `Write report`.
- **AC-06.3** — Matching ignores upper and lower case — searching `REPORT` returns `Write report`.
- **AC-06.4** — Only the title is searched. A term that appears solely in a description does not
  match.
- **AC-06.5** — A term matching nothing responds `200 OK` with an empty collection, never `404`
  and never an error.
- **AC-06.6** — Omitting the search parameter returns the full list, exactly as US-02.
- **AC-06.7** — A search parameter that is empty or whitespace-only is treated as no search at
  all and returns the full list.
- **AC-06.8** — Results remain ordered newest first.
- **AC-06.9** — Search is applied by the database query, not by loading every task and filtering
  in memory.
- **AC-06.10** — The search is executed asynchronously.

## Traceability

**Satisfies**: FR-017, FR-018, FR-020, FR-021, FR-027

**Verified by success criteria**: SC-005

## Out of scope

The search input control (US-12). Searching descriptions. Fuzzy, phonetic or ranked matching.
Search term highlighting.

## Definition of done

Demonstrated in Swagger: a mid-word match, a case-mismatched match, a term that matches nothing, a
whitespace-only term, and an omitted parameter.
