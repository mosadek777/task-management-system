# US-05 — Delete a task

| Field | Value |
|---|---|
| **ID** | US-05 |
| **Layer** | Backend |
| **Actor** | Task owner |
| **Linked endpoint** | `DELETE /api/tasks/{id}` |
| **Spec user story** | Story 5 — Remove a task (P2) |
| **Priority** | P2 |

## Description

As the task owner, I want to permanently remove a task so that work I entered by mistake, or that
is no longer relevant, stops cluttering my list. Removal is irreversible — there is no archive and
no restore.

## Acceptance criteria

- **AC-05.1** — Deleting an existing task removes it permanently and responds `204 No Content`.
- **AC-05.2** — The deleted task is absent from every subsequent retrieval, search and filter.
- **AC-05.3** — Retrieving the deleted task by its identifier afterwards responds `404 Not Found`.
- **AC-05.4** — Deleting an identifier that does not exist responds `404 Not Found` and changes
  nothing else.
- **AC-05.5** — Deleting the same task twice responds `204` then `404`; the second attempt is not
  treated as an error state beyond the `404`.
- **AC-05.6** — No "deleted" flag, archive copy or hidden retention of any kind exists. The record
  is genuinely gone.
- **AC-05.7** — Deleting one task never affects any other task.
- **AC-05.8** — The read and the removal are both performed asynchronously.

## Traceability

**Satisfies**: FR-014, FR-016, FR-026, FR-030

**Verified by success criteria**: SC-004, SC-009

## Out of scope

The confirmation prompt shown to the person — that is a client responsibility (US-11). Undo,
restore, recycle bin, soft delete. Bulk deletion.

## Definition of done

Demonstrated in Swagger: delete succeeds, the same identifier then returns `404` on retrieval, the
task is absent from the full list, and a second delete returns `404`.
