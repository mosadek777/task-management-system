# US-04 — Update an existing task

| Field | Value |
|---|---|
| **ID** | US-04 |
| **Layer** | Backend |
| **Actor** | Task owner |
| **Linked endpoint** | `PUT /api/tasks/{id}` |
| **Spec user story** | Story 4 — Keep a task up to date (P2) |
| **Priority** | P2 |

## Description

As the task owner, I want to change a stored task so that I can correct its details, adjust its
importance or due date, and advance it through Todo → InProgress → Done. The update replaces the
editable values of the task identified in the address.

## Acceptance criteria

- **AC-04.1** — Updating an existing task with valid values responds `200 OK` with the updated
  task.
- **AC-04.2** — The title, description, importance, state and due date are all changeable.
- **AC-04.3** — The identifier is never changed by an update; the identifier in the address is
  authoritative and any identifier in the body is ignored.
- **AC-04.4** — The capture moment is never changed by an update.
- **AC-04.5** — A state change to Done is stored and reflected in every subsequent read.
- **AC-04.6** — The description and the due date can each be cleared back to absent.
- **AC-04.7** — Every validation rule from US-01 applies identically: title required and trimmed,
  title at most 200 characters, description at most 1000 characters, importance and state within
  the permitted sets.
- **AC-04.8** — A rejected update responds `400 Bad Request`, names the offending value, and
  leaves the stored task completely unchanged.
- **AC-04.9** — Updating an identifier that does not exist responds `404 Not Found` and creates
  nothing — a `PUT` to a missing identifier never results in a new task.
- **AC-04.10** — A due date in the past is accepted.
- **AC-04.11** — The read and the save are both performed asynchronously.

## Traceability

**Satisfies**: FR-010, FR-011, FR-012, FR-013, FR-022, FR-023, FR-024, FR-025, FR-026, FR-028

**Verified by success criteria**: SC-002, SC-003, SC-009

## Out of scope

The edit form (US-10). Partial updates of single fields. Change history or audit trail.
Concurrency tokens.

## Definition of done

Demonstrated in Swagger: a successful change to every editable field, a validation rejection that
leaves stored data untouched, and a `404` against a missing identifier confirming nothing was
created.
