# US-01 — Create a task

| Field | Value |
|---|---|
| **ID** | US-01 |
| **Layer** | Backend |
| **Actor** | Task owner (the single user of the system) |
| **Linked endpoint** | `POST /api/tasks` |
| **Spec user story** | Story 1 — Capture a task (P1) |
| **Priority** | P1 |

## Description

As the task owner, I want to submit a new task so that the work is recorded and available in my
list. The system accepts a title, an optional description, an importance, a state and an optional
due date, assigns the task a unique identifier, stamps it with the moment it was captured, and
stores it.

## Acceptance criteria

- **AC-01.1** — Submitting a valid task stores it and responds `201 Created`.
- **AC-01.2** — The response body contains the stored task including its newly assigned
  identifier and the recorded capture moment.
- **AC-01.3** — The response carries a `Location` header pointing at the new task's own address.
- **AC-01.4** — The identifier is generated by the system, is unique, and any identifier supplied
  by the caller is ignored rather than honoured.
- **AC-01.5** — The capture moment is set by the system in UTC and cannot be supplied by the
  caller.
- **AC-01.6** — Submitting with a missing, empty or whitespace-only title is rejected with
  `400 Bad Request` and a message naming the title.
- **AC-01.7** — The title is trimmed before validation; a trimmed title of one or more characters
  is accepted. There is no minimum length.
- **AC-01.8** — A title longer than 200 characters is rejected with `400` and a message stating
  the limit. The text is never silently shortened.
- **AC-01.9** — A description longer than 1000 characters is rejected with `400` and a message
  stating the limit.
- **AC-01.10** — Omitting the description and the due date is accepted; both are stored as absent.
- **AC-01.11** — Omitting the importance stores the task as Medium. Omitting the state stores it
  as Todo.
- **AC-01.12** — An importance or state outside the permitted set is rejected with `400`.
- **AC-01.13** — A due date in the past is accepted exactly like any other date. No date-range
  validation exists.
- **AC-01.14** — Validation is performed by the server itself and cannot be bypassed by any
  caller, regardless of what the browser did or did not check.
- **AC-01.15** — When a submission is rejected, nothing is stored.

## Traceability

**Verified by success criteria**: SC-001, SC-003

## Out of scope

Client-side form behaviour (US-09). Bulk or repeated creation. Supplying an identifier or a
capture moment from outside.

## Definition of done

All acceptance criteria demonstrated against the running endpoint in Swagger, including at least
one rejection case, with the stored result confirmed by a subsequent read.
